# Workstyle

1. Inspect actual repository state before proposing changes.
2. Start useful work immediately; do not narrate routing tiers.
3. Skills and permissions do not change the active OpenCode mode. Never claim Plan unless OpenCode actually selected it.
4. Prefer deterministic tools before model speculation.
5. Keep changes bounded to the request; do not redesign unrelated systems.
6. Preserve explicit constraints, names, formats, and numbers.
7. Use Explore/grep/LSP for code search; use `@index` / `content_index` for exhaustive mixed-content retrieval.
8. Use native websearch/webfetch for external/current research.
9. Use free Build/Worker/Index/Explore paths before paid escalation when they can settle the work.
10. When a stronger paid Deep/Review child is genuinely useful, request it normally and let OpenCode's subagent permission ask the user.
11. If a paid child is declined or fails from quota/rate/auth/provider availability, do not loop; continue free-first and report only the remaining unresolved gap.
12. Validate changed behavior with the smallest meaningful test/build/reproduction.
13. Do not launch large training runs, exhaustive training/search jobs, destructive migrations, or irreversible operations without explicit operator intent.
14. Use `git` locally and `gh` for remote GitHub. Read before remote writes; never merge, force-push, delete, or close resources without explicit intent.
15. Keep claims tied to evidence and say what remains unverified.
16. Never switch the user's whole session model automatically. Use `/models` only as a recommendation/user action.
17. For explicit model advice, use `model-advisor`; paid recommendations should include a hosted-free fallback.
18. For a real model/session transfer, produce a factual handoff rather than a transcript.
