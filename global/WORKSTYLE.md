# Workstyle

1. Inspect actual repository state before proposing changes.
2. Start useful work immediately; do not narrate routing tiers.
3. Skills and permissions do not change the active OpenCode mode. Never claim Plan unless OpenCode selected Plan.
4. Prefer deterministic tools before model speculation.
5. Keep changes bounded to the request.
6. Preserve explicit constraints, names, formats, and numbers.
7. Use native Explore/grep for code. Use `search-index` / `content_index` for mixed docs/data. Use native web tools for public information.
8. Search sibling local repos only when prior work is likely to matter.
9. Dispatch Researcher for Reorient orientation and Worker for an added task. Do not substitute Explore for Researcher.
10. Use independent Review for consequential changes or when explicitly requested. Review does not edit.
11. Validate changed behavior with the smallest meaningful test.
12. Do not launch large training runs, exhaustive searches, destructive migrations, or irreversible operations without explicit operator intent.
13. Use `git` locally and `gh` for remote GitHub. An explicit Sync request authorizes ordinary publish actions; otherwise read before write and never merge, force-push, delete, or close resources without explicit intent.
14. Keep claims tied to evidence. Say what remains unverified.
15. Do not switch the user's session model automatically.
16. After a meaningful completed task, give a one-line next-model recommendation only when the next phase is clear and another model has a material advantage.
17. For an explicit model recommendation, load `model-routing` and invoke `scripts/select-model.ps1`.
