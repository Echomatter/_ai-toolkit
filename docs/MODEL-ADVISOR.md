# Model Advisor

The toolkit separates **delegation** from **promotion**.

## Delegation

When one bounded part of an active task needs stronger reasoning, Build may send only that part to `@deep`. The parent session stays on its current model.

## Promotion

When the **rest of the phase** broadly benefits from a stronger model, the toolkit recommends a model but does not switch automatically. Use OpenCode's `/models` selector to promote the current session explicitly.

This keeps routing visible and avoids surprising model changes between unrelated tasks.

## Automatic completion advice

The global OpenCode guidance contains the current generated Routine, Deep, and Review assignments. At the end of a meaningful completed task, Build may append a single `Next model:` line only when:

1. the likely next phase is clear;
2. another lane has a material capability advantage; and
3. that recommendation would change what should happen next.

No recommendation is emitted when the current model remains adequate or the next phase is unclear.

This completion check does **not** make another model call. It rides on the response that already completed the task.

## Explicit recommendation

Use:

```text
/recommend-model <next phase>
```

The `model-advisor` skill can inventory current OpenCode models and connected OAuth providers. For a material or ambiguous choice, it can use current web research to compare official capabilities and task-relevant independent evidence.

Recommendations are limited to:

- current OpenCode free models;
- OpenAI OAuth / ChatGPT subscription models;
- GitHub Copilot OAuth subscription models;
- optional local Ollama models.

Separately metered API gateways/providers remain outside automatic advice.

## Evidence policy

Use official provider/model documentation for concrete capabilities such as context, tool support, and reasoning controls. For coding quality, use recent task-relevant evidence such as coding-agent evaluations, SWE-bench, or Terminal-Bench when useful.

Benchmark results depend on the harness, settings, and task. They are evidence, not a universal model ranking.

## Current roster

`routing/model-roster.json` is regenerated by `scripts/refresh-routing.cmd`. It records the currently eligible non-metered model IDs, their access surfaces, and the configured Routine/Deep/Review assignments.
