# Architecture

```text
OpenCode Desktop
 |
 |-- Build (native primary ID; toolkit assigns routine/free model)
 |    |-- Explore (native read-only source-code search)
 |    |-- Index (free mixed-corpus retrieval)
 |    |-- Deep    (toolkit subagent; strong subscription model)
 |    `-- Review  (toolkit subagent; independent read-only model)
 |
 |-- Plan (native; user selects explicitly)
 |
 |-- /recommend-model
 |    `-- model-advisor skill -> stay / delegate / review / manual /models promotion
 |
 |-- native websearch/webfetch
 |-- git + gh
 |-- ~/.agents/skills/*
 `-- ~/.config/opencode/AGENTS.md
      `-- toolkit-managed global routing/advice block + preserved user content
```

OpenCode owns the execution harness, provider/model plumbing, `/models`, tools, permissions, context management, and child sessions. The toolkit does not duplicate those systems.

The Desktop app loads the toolkit's Build/Index/Deep/Review definitions through `~/.config/opencode/agents/`. Custom slash commands are installed in `~/.config/opencode/commands/`.

The toolkit-managed block in global `AGENTS.md` carries current Routine/Index/Deep/Review assignments and sparse next-phase recommendation behavior. It is regenerated by `refresh-routing.cmd` and merged without replacing user-authored global instructions.

Scout is not part of the stable dependency surface for this toolkit. External research stays in Build using native web tools.

The global `content_index` custom tool wraps the toolkit-owned Python indexer. It is deterministic retrieval infrastructure, not another model router.
